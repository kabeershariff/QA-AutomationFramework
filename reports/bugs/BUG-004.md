# BUG-004: Resume file type and size are advertised but never enforced

- Severity: Major
- Priority: P2
- Status: Open; reproduced 2026-10-14
- Environment: Chromium 1280x720; local portal copy (`mock_site`) on `http://127.0.0.1:8765`
- Scenario: `simple-company-form`
- Preconditions: none
- Steps to reproduce:
  1. Open `/jd?scenarios=simple-company-form&id=0&dataset=big_company_cs_1000`.
  2. Note the `accept` attribute on the `Resume` input: `.pdf,.doc,.docx`.
  3. Select `probe-evil.exe`, a 10-byte file containing `MZ\x90\x00binary`.
  4. Observe the file list under the input, and the number of field-level errors.
  5. Repeat with a zero-byte file named `probe-empty.pdf`.
- Expected result: A disallowed extension is refused with a user-facing message naming
  the accepted types, and a zero-byte file is refused as empty. `accept` is a file-picker
  hint only; the check must be repeated in code.
- Actual result: Both files are accepted and listed as valid resumes, with their real
  MIME types and sizes recorded. No error of any kind is shown.
- Evidence:

  | Probe | Result |
  |---|---|
  | `#field-resume` `accept` attribute | `.pdf,.doc,.docx` |
  | Selected `probe-evil.exe` | listed as `probe-evil.exe (application/x-msdownload, 10 bytes)` |
  | Selected `probe-empty.pdf` | listed as `probe-empty.pdf (application/pdf, 0 bytes)` |
  | `[data-field-error]` elements rendered | **0** |

- Frequency: always
- Notes / suspected root cause: `FileInput.tsx:29-40` records whatever the change event
  delivers:

  ```tsx
  const handleChange = (e: ChangeEvent<HTMLInputElement>) => {
    const files = e.target.files;
    if (!files) { onChange([]); return; }
    const metas: SubmissionFileMetadata[] = [];
    for (const file of Array.from(files)) {
      metas.push(fileToMetadata(name, file));
    }
    onChange(metas);
  };
  ```

  The `accept` prop is passed straight to the `<input accept=...>` attribute and is never
  checked against the chosen file. `FileInputProps` declares an `error` prop and renders
  `role="alert"` markup for it (`:72-76`), but `simple-company-form/index.tsx:85-94`
  never passes an `error`, so that channel is unused. `validateRequired`
  (`validation.ts:38-42`) checks only that *some* file exists, never what it is.
- Impact: an executable or an empty file is recorded as an applicant's resume. Even in
  this frontend-only build the metadata is what any downstream system would key on, and
  there is no size ceiling at all, so an arbitrarily large upload is accepted.
- Suggested fix: validate the selection in `handleChange` against the `accept` list and a
  documented maximum size, pass the failure through the existing `error` prop so it is
  announced via `role="alert"`, and exclude rejected files from `onChange`.
- Automated coverage: `tests/application_form/test_application_form.py`
  ::`test_resume_rejects_disallowed_extension_and_empty_file` currently passes only in
  its `xfail(strict=True)` form; see the inline reason.
- Retest: pending fix.
