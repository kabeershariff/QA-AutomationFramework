# BUG-006: Empty "Salary:" and "Experience:" pills render for datasets that carry neither value

- Severity: Minor
- Priority: P3
- Status: Open; reproduced 2026-10-14
- Environment: Chromium 1280x720; local portal copy (`mock_site`) on `http://127.0.0.1:8765`
- Dataset: `big_company_cs_1000`
- Steps to reproduce:
  1. Open `/`.
  2. Read the first job card's salary and experience pills.
  3. Open `/jd?scenarios=simple-company-form&id=0&dataset=big_company_cs_1000` and read
     the same two pills on the detail page.
- Expected result: The 1000-row dataset has no `salary` or `experience` field on any
  record (verified by parsing `mock_site/public/data/big_company_cs_1000.jsonl`). Either
  the pills are omitted entirely, or they read as unavailable rather than as a label
  with nothing after it.
- Actual result: Both pills render with the label and no value — literally `Salary:` and
  `Experience:` — on the listing (50 rows per page, so 50 empty pills at a time) and on
  the detail page.
- Evidence:

  | Location | Rendered text |
  |---|---|
  | Listing, first card `[data-job-salary]` | `Salary:` |
  | Listing, first card `[data-job-experience]` | `Experience:` |
  | Detail, `[data-jd-salary]` | `Salary:` |
  | Detail, `[data-jd-experience]` | `Experience:` |

  Index status on the same page: `big_company_cs_1000 · 1-50 of 1000 · Static-only JSON echo`.
  For contrast, the 3-row `qa_fake_jobs` dataset renders fully populated pills, e.g.
  `Salary: $90,000 - $110,000 per year`.
- Screenshot: `reports/bugs/evidence/BUG-006-empty-salary-pills.png`
- Frequency: always
- Notes / suspected root cause: the pills are rendered unconditionally in both components.
  `Home.tsx:82-87`:

  ```tsx
  <span data-job-salary="" ...>Salary: {job.salary}</span>
  <span data-job-experience="" ...>Experience: {job.experience}</span>
  ```

  and `ScenarioFrame.tsx:316-321`:

  ```tsx
  <span data-jd-salary="" ...>Salary: {jsonlJob.salary}</span>
  <span data-jd-experience="" ...>Experience: {jsonlJob.experience}</span>
  ```

  `job.salary` is `undefined` for every record in this dataset, and React renders
  `undefined` as nothing, leaving a bare label inside a styled pill. There is no
  `job.salary &&` guard, unlike the legacy JD branch a few lines below
  (`ScenarioFrame.tsx:612`) which *does* guard with `{jd.salaryRange && (...)}`.
- Impact: low severity, but it directly harms the scope item *"verify that job titles,
  salaries, experience requirements, and descriptions are displayed correctly"* — a
  reader scanning the default dataset sees 50 misleading pills per page. It also means a
  naive `assert_non_empty_strings(job_salaries())`-style check passes on the label while
  the value is missing.
- Suggested fix: render the pill only when the underlying value is present, matching the
  existing guard style at `ScenarioFrame.tsx:612`.
- Automated coverage: `tests/job_listings/test_job_listings.py::test_missing_salary_and_experience_are_not_shown_as_empty_pills`
  is `xfail(strict=True)`.
- Retest: pending fix.
